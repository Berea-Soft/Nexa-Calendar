# Security Policy

## Supported Versions

| Version | Supported          |
| ------- | ------------------ |
| 1.x.x   | :white_check_mark: |
| 0.x.x   | :x:                |

## Reporting a Vulnerability

If you discover a security vulnerability within Nexa-Calendar, please follow our
responsible disclosure process:

1. **Do NOT** create a public GitHub issue
2. Send a detailed description of the vulnerability to: https://github.com/Berea-Soft/Nexa-Calendar/security/advisories/new
3. Allow time for the team to assess and fix the vulnerability
4. Once fixed, you will be credited in the release notes (if desired)

## Security Best Practices

When using Nexa-Calendar in your projects:

- Keep dependencies up to date
- Validate all event data on your server-side
- Use Content Security Policy headers appropriately
- Sanitize user input before passing to calendar components

## Known Issues

For a full list of known security advisories, please refer to the
[GitHub Security Advisories](https://github.com/Berea-Soft/Nexa-Calendar/security/advisories)
page.
